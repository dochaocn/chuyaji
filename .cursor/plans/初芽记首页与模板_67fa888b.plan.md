# 初芽记首页信息架构 + 记录模板体系

## 设计目标

- 产品定位收敛为：`好用、温和、持续陪伴的母婴记录工具`。
- 不把首页做成信息堆叠页，而是做成 `现在该做什么` 的决策页。
- 不把记录做成通用表单，而是做成 `按场景进入的模板化记录`。
- 尽量复用现有页面与数据模型：宝宝首页、宝妈首页、记录编辑页、`record_type` 枚举、`payload` 扩展字段。

## 核心产品原则（贯穿全篇）

- **温和，不催促**：首页默认不显示任何"下一步"催促条，仅在三种情况出现（见后文）。
- **碎片化优先**：高频低门槛记录（喂养、排便、睡眠、心情）走"一键记录"；重结构化记录（产检、B 超、生长、疫苗）走"标准模板"。
- **字段分层**：每个模板只显式展示 1-3 个推荐字段，其余收进"更多"折叠区，避免一次性把用户吓退。
- **就地升级，不造新层**：模板注册表扩展在现有 `utils/*RecordTypes.ts`，保持旧消费方（如 `labelForType`）向后兼容。

## 一期范围收敛（最终执行边界）

- **仅支持单档案**：当前用户只维护一个宝宝 + 一个宝妈档案；虽然后端 `apiListBabies / apiListMothers` 已支持多条，但一期首页不做切换入口。
- **孕周统一按 EDD 反推**：有 `edd_date` 时按 `EDD - 今天 = 剩余孕周`，反推当前孕周；未填 EDD 时才用 `LMP + 280 天` 推算；这是和医生口径一致的唯一口径。
- **宝宝-宝妈联动**：创建宝宝档案时，若当前用户已有宝妈档案，自动从 `mother.delivery_date` 预填 `baby.birth_date`，从宝妈档案的医院信息（如有）预填 `birth_hospital`；用户可修改。
- **下一步卡片统一阈值**：一期统一使用“距上次任何记录超过 7 天”作为“很久没记”的判断标准，不做按记录类型区分。

## 首页信息架构

### 1. 首页统一原则

两个 Tab 都采用四层结构，自上而下固定：

1. `阶段头部`：告诉用户当前处于什么阶段（不催促，只陪伴）。
2. `下一步卡片`：**按需出现**，仅三种情况触发。
3. `快捷记录区`：4 个固定入口，按 `mode` 分为一键记录与标准记录。
4. `最近记录 / 趋势摘要`：让用户回看并获得反馈。

### 2. 下一步卡片出现规则（关键约束）

首页默认**不显示**该卡片。仅以下三种情况出现，且最多出现 1 张：

1. **未建档**：没有宝宝/宝妈档案 -> `创建档案`。
2. **很久没记**：距上次任何记录超过 7 天 -> `补一条最近记录`。
3. **有到期事项**：存在未来 3 天内的检查/疫苗/复诊提醒 -> `查看提醒`。

其他情况（即便是"最近无体重记录"）一律不显示。避免首页变成"小红点催促条"，与"温和陪伴"定位冲突。

不做快捷入口“淡化”这类中间态视觉。若下一步卡片与下方快捷入口指向同一动作，快捷入口仍保持正常展示，避免用户误解为不可用或次要功能。

**宝妈 Tab 补充（未建档唯一性与双入口）**：宝妈首页以「是否已有宝妈档案」为未建档判断。此时**不得**同时展示「下一步」里的建档提示与下方另一块「仅宝妈建档」空状态（否则会出现两张卡、两个按钮却都指向宝妈建档）。实现上：**尚无宝妈档案时，不展示「下一步」中的建档卡片**，只保留**一块**空状态区域；该区域内并列提供 **「创建宝宝档案」** 与 **「创建宝妈档案」** 两个入口（与全局「未建档」语义一致：宝宝/宝妈二选一或先后建立，一期仍单宝宝、单宝妈）。

### 3. 宝宝首页

#### A. 阶段头部

显示：

- 宝宝昵称
- 当前阶段：`怀孕期 / 成长期`（依据 `birth_date` 是否已过今天判断）
- 一句陪伴文案，不含任何 CTA

示例：

- 怀孕期：`今天是孕 24 周 3 天，继续把每次检查安心记下。`（孕周按 EDD 反推）
- 成长期：`宝宝出生第 86 天，喂养和生长变化都值得记一记。`

#### B. 下一步卡片（按需）

遵循全局三种触发规则，不额外扩展。

#### C. 快捷记录区（固定 4 个）

按阶段切换一组固定入口，每个入口带 `mode` 标识：

怀孕期（全部 `mode: standard`）：

- 产检
- B 超
- 症状
- 用药

成长期快捷入口按月龄切换：

- `0-6 月`：喂养（一键）、睡眠（一键）、排便（一键）、生长（标准）
- `6 月后`：喂养（一键）、睡眠（一键）、生长（标准）、疫苗（标准）

`mode: quick` 点击后弹底部极简面板，只 1-2 个数值字段 + 一键保存；`mode: standard` 走完整模板页。

#### D. 趋势摘要

替代现有单一体重摘要，升级为 2-3 张轻量卡片：

- 最近体重 + 距上次记录天数
- 本月记录数
- 成长期：最近一次里程碑（若有 development 记录）

如果没有生长数据，则整块隐藏，不显示占位。

#### E. 最近记录

- 默认展示最近 3 条
- 提供 `查看全部时间线` 入口

### 4. 宝妈首页

和宝宝页区分出角色感，不只换文案。

#### A. 阶段头部

显示：

- 称呼
- 当前阶段：`怀孕中 / 产后恢复 / 育儿期`
- 一句陪伴文案，不含任何 CTA

示例：

- 怀孕中：`这一阶段最重要的是把检查、身体感受和情绪稳稳记下。`
- 产后恢复：`恢复节奏不必着急，把身体和心情慢慢记下来。`

#### B. 下一步卡片（按需）

遵循全局三种触发规则。若当前**尚无宝妈档案**，「未建档」对应的引导由 **D. 未建档空状态** 单独承接，**不再**在此处重复出现第二张「去建档」卡片（见上文「宝妈 Tab 补充」）。

#### C. 快捷记录区（固定 4 个，不按阶段替换）

- 产检/复查（标准）
- 症状（标准）
- 心情（一键）
- 身体指标（一键，默认进入最近常用项：体重 / 血压 / 血糖；若没有使用历史，则首次进入体重）

阶段差异只体现在 `阶段头部文案` 和 `下一步卡片内容`，快捷入口位置保持稳定，避免用户迷路。

#### D. 健康摘要

替代现在静态的"记录数/最近更新"，改为：

- 最近一次产检日期
- 最近一次身体指标（体重/血压/血糖 任一）
- 最近一次心情记录

三者中有几条显示几条，都没有则整块隐藏。

#### E. 最近记录

- 默认展示最近 3 条
- 提供 `查看全部记录` 入口

#### F. 未建档空状态（无宝妈档案）

- **仅一块**提示区：标题/说明中性表述「还没有档案」类，**并列两个主按钮**：`创建宝宝档案`（跳转宝宝档案编辑）、`创建宝妈档案`（跳转宝妈档案编辑）。
- 若本地会话已有宝宝 `id`，「创建宝宝档案」进入编辑态；无则新建。与宝宝 Tab 的建档能力对齐，避免用户只能从宝妈 Tab 建宝妈档。

### 5. 首页空状态原则

所有空状态都给明确下一步，不只给说明：

- 未登录 -> `登录并开始记录`
- 未阅读隐私说明 -> `先阅读隐私说明`
- 未建档 -> `创建档案`
- 无记录 -> `从推荐模板开始`

## 记录模板体系

### 设计原则

- 模板 = `记录类型 + 模式 + 推荐字段 + 可选字段 + 摘要提示 + 附件建议`。
- 每条记录仍然保存到现有 `summary + payload + attachments`。
- **字段分层**：推荐字段 1-3 个默认展示；可选字段收进"更多"折叠区。
- **两种模式**：
  - `quick`：用于喂养、睡眠、排便、心情这类高频低门槛场景；底部面板，只 1-2 字段，一键保存。
  - `standard`：用于产检、B 超、生长、疫苗、疾病等重结构化场景；完整模板页。
- **摘要策略**：`quick` 模式默认不要求用户填写摘要，保存时由系统自动生成摘要文案。

### 1. 宝宝模板体系

#### 怀孕期模板（全部 standard）

1. `prenatal_checkup / 产检`

- 推荐字段：孕周、医生建议、下次时间
- 可选字段：医院、检查项目、结果
- 摘要提示：`今天产检结果如何？有没有医生特别提醒？`
- 附件建议：检查单、报告单

1. `ultrasound / B 超`

- 推荐字段：孕周、胎儿估重、医生结论
- 可选字段：医院、BPD、HC、AC、FL、胎心
- 摘要提示：`B 超整体情况如何？`
- 附件建议：B 超单、影像照片

1. `nt / NT`

- 推荐字段：NT 值、结论
- 可选字段：医院、孕周
- 摘要提示：`NT 检查结果如何？`

1. `screening / 筛查`

- 推荐字段：筛查类型、结论
- 可选字段：风险提示、医生建议
- 摘要提示：`筛查结果和医生建议是什么？`

1. `glucose_test / 糖耐`

- 推荐字段：结论
- 可选字段：空腹、1 小时、2 小时
- 摘要提示：`糖耐结果是否正常？`

1. `symptom / 不适`

- 推荐字段：症状类型、严重程度
- 可选字段：持续时间、是否就医
- 摘要提示：`今天最明显的不适是什么？`

1. `medication / 用药`

- 推荐字段：药名、用途
- 可选字段：剂量、开始日期、医生建议
- 摘要提示：`因为什么开始用药？效果如何？`

## 模板落地方式

### 1. 结构层（就地升级，不新建目录）

将现有 `RECORD_TYPES` 与 `MOTHER_RECORD_TYPES` 从"值/标签数组"就地升级为"模板注册表"，TypeScript 类型示意如下：

```ts
type RecordTemplate = {
  value: string;
  label: string;
  entryLabel: string;
  mode: "quick" | "standard";
  recommendedFields: TemplateField[];
  optionalFields: TemplateField[];
  summaryPlaceholder?: string;
  autoSummary?: (payload: Record<string, unknown>) => string;
  attachmentHint?: string;
  metricKeys?: string[];
};

type TemplateField = {
  key: string;
  label: string;
  placeholder?: string;
  type: "text" | "number" | "date" | "select";
  unit?: string;
  options?: { value: string; label: string }[];
};
```

改造文件（**就地扩展，不新建 features/records/**）：

- [apps/miniapp/src/utils/recordTypes.ts](/Users/Zhuanz1/chuyaji/apps/miniapp/src/utils/recordTypes.ts)

## 验收标准

- 用户第一次进首页，在未建档状态下仅看到一张"创建档案"卡片，无其他干扰。
- **宝妈 Tab**：尚无宝妈档案时，不出现「下一步」建档卡片与下方建档空状态**重复**；**同屏仅一块**建档相关区域，且必须同时提供 **创建宝宝档案** 与 **创建宝妈档案** 入口（不得两块区域都只引导宝妈建档）。
- 首页默认状态下**不出现**"下一步"卡片，仅在三种触发条件命中时出现且最多一张。
- 宝妈首页快捷入口在三种阶段下位置不变，仅头部文案不同。
- 宝宝成长期首页在 `0-6 月` 与 `6 月后` 展示不同的 4 个固定入口，且切换规则仅由月龄决定。
- 高频场景（喂养、睡眠、心情、体重、血压、血糖、排便）可以在不跳页的情况下 1-2 步完成记录。
- 每个标准模板的推荐字段不超过 3 个，其余一律折叠。
- quick 模式默认不展示摘要输入，保存后能自动生成可读摘要。
- 孕周展示在宝宝与宝妈首页完全一致，且与医生口径（按 EDD）吻合。
- 新建宝宝档案时，若用户已有宝妈档案，出生日期默认已填。
- 模板新增或修改时，只改一个注册表文件，首页、记录页、摘要全部跟随。
- 当前仅支持单宝宝、单宝妈档案，UI 不出现切换入口。
